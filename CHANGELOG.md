# Changelog

## 1.0.0 — stable feature baseline
- Promoted the 0.9.x feature set to the 1.0.0 baseline without changing server metadata or property-file formats.
- Reconfirmed version-aware `server.properties` behavior: create the world with the selected server build first, expose only settings that build generated, reject unsupported keys, and preserve unknown native properties.
- Kept `online-mode=false` as a managed default only when the selected server build emits that property.
- Added release documentation that distinguishes local/offline verification from real-host production acceptance.
- No automatic migration or overwrite of existing worlds is performed. Back up server data before upgrading the IlandyMC application.


## 0.9.0 — detect properties from the installed server build
- Changed first-install flow: after downloading the exact server artifact, IlandyMC starts it in an isolated staging directory so the server itself creates its world and native `server.properties`.
- Bootstrap binds to loopback on port `0`, disables RCON during generation, waits for the server-ready log marker, then sends `stop` and requires a clean shutdown before atomic install commit.
- The editor now intersects the documented catalogue with keys actually generated by that exact server version. Missing/unsupported settings are hidden in TUI and CLI and are rejected if manually submitted.
- The installer never seeds the server with the full 26.3 template; it preserves server-generated and unknown keys and only applies Ilandy-managed defaults when those keys exist.
- `online-mode=false` and loopback RCON remain defaults when supported by the installed build.
- Added regression tests for old-version key filtering and generated-property bootstrap.


## 0.8.0 — documented server.properties editor
- Added a 71-option Minecraft 26.3-style `server.properties` catalogue with a Russian label and description for every setting.
- Reworked the TUI settings area into a scrollable editor: booleans use switches, enumerations use selectors, and numeric/text settings use inputs; each control is followed by its explanation.
- Added CLI inspection/editing with `server-properties SERVER` and repeatable `--set KEY=VALUE`.
- New server defaults are based on the uploaded properties template, with `online-mode=false`; built-in Management API is disabled and secrets/personal MOTD are not carried into the default template.
- Property writes validate types/ranges, preserve unknown keys, save atomically, and synchronize gameplay/RCON port metadata and the internal RCON secret.
- Editing is refused while the process manager or an installed systemd service reports the server active.

## 0.7.0 — TUI launcher, managed install and verified updates
- Added the `ily` command as a dedicated Textual TUI launcher with server selection, start/stop, settings, and update controls.
- Added stopped-server configuration for RAM and gameplay port.
- Added opt-in automatic application updates from an administrator-configured HTTPS JSON manifest; release wheels are SHA-256 verified before pip installation into `/opt/ily/venv`.
- Added a root-only bootstrap installer that installs into `/opt/ily` and exposes `ily` and `ilandy` in `/usr/local/bin`.

## 0.5.0 — Minecraft 2026 compatibility and Paper API refresh
- Added Minecraft's 2026 `YY.drop[.hotfix]` release format, including 26.x prerelease suffixes. Vanilla discovery now lists release-channel versions only.
- Updated Java requirement detection: Minecraft 26.x requires Java 25; legacy release rules remain supported.
- Replaced deprecated Paper v2 downloads endpoints with PaperMC Fill v3.
- Paper version discovery now handles grouped version lists and preserves service ordering.
- Paper installs now select STABLE builds only and consume published SHA-256 checksums when present.
- Updated the Paper API User-Agent and CLI examples; added regression tests for version policy and v3 responses.

## 0.4.0 — reliability and test increment
- Hardened process lifecycle with Linux /proc start-time identity checks and zombie handling.
- Added atomic Linux no-replace install commit to prevent concurrent destination clobbering.
- Enforced HTTPS-only artifact metadata and explicit supported checksum algorithms.
- Made TUI import lazy so headless CLI/help works without Textual installed.
- Expanded offline integration/security tests, test guide and release checklist.
- Improved backup uniqueness and restore tamper/traversal coverage.

## 0.3.0 — engineering increment
- Added transactional first-time server installation, loopback RCON and staged backups/restores.

## 0.6.0

- Added explicit game-port configuration (`--port`, default 25565) and persisted it in server metadata and `server.properties`.
- Added systemd service lifecycle commands: `service-install`, `service-status`, and `service-uninstall`.
- Added creation/reuse of a dedicated unprivileged system account, refusal to run services as root, restrictive directory ownership transfer, and atomic unit-file installation.
- Hardened generated units with filesystem, kernel, device, privilege, and file-descriptor restrictions.
- Added validation for service names, users, paths, Java executable, memory, JAR names, restart policy, and timeouts.
